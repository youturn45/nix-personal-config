# CLAUDE.md

Nix configuration for macOS (nix-darwin) and NixOS. Uses Flakes with automatic module discovery. Claude cannot run Nix builds — review code only, user runs builds.

## Systems

| Host | Role | Config |
|---|---|---|
| Rorschach | Laptop, daily driver | `hosts/darwin/Rorschach.nix` |
| SilkSpectre | Laptop, daily driver | `hosts/darwin/SilkSpectre.nix` |
| NightOwl | Mac Mini, server | `hosts/darwin/NightOwl.nix`, `hosts/darwin/NightOwl/server.nix` |

All system settings, including `.config`, are managed through this flake — no out-of-band dotfile edits.

## Structure

- System-level (root) → `modules/`; user-level (dotfiles, packages) → `home/`. Both split into `common/`, `darwin/`, `nixos/` per platform; cross-platform code branches on `pkgs.stdenv.isDarwin`.
- Modules auto-discovered via `collectModulesRecursively` (`my-lib/default.nix`): `_`-prefixed files/dirs ignored, a directory's own `default.nix` excluded from recursion, nested `*/default.nix` overrides sibling files. Never both explicitly import a subdirectory and let it be auto-collected.
- All variables in `vars/default.nix` as `myvars.*` — never hardcode usernames/paths.

## Before Committing

Correct module placement, no hardcoded paths/usernames, no unencrypted secrets, platform conditionals present where needed.

## Notes

Theme: Catppuccin Mocha. NixVim via `home-manager.sharedModules`. State versions in `vars/default.nix` — don't change without reason.

**Claude Code settings:** `~/.claude/settings.json` is generated by `home/common/claude-code/default.nix` — edit allowlists there, not the file directly. Per-repo allowlists go in `.claude/settings.json` committed in that repo. Never use `.claude/settings.local.json` — it's untracked and won't survive a rebuild.

**Shell config:** Never edit `~/.zshrc` (or other dotfiles) directly — the system is Nix-managed and out-of-band edits get clobbered on rebuild. Change shell settings via `home/common/terminal/shells/default.nix` instead.
